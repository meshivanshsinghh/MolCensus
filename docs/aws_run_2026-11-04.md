# MolCensus: AWS GPU run of 2026-11-04

MolCensus benchmarks optical chemical structure recognition (OCSR) tools on whole scientific PDFs.
It renders the pages, detects molecule drawings with MolDetV2, reads each drawing as SMILES and
scores each tool against a ground-truth list of the molecules in six course papers (AAI 6630,
Northeastern University, Fall 2026). This file sums up the overnight run on AWS (folder
`20261104T012009Z` in the S3 bucket): what came back, the scores, a reproducibility check and the
problems found.

Three crop readers were compared: **MolScribe**, **MolSight** (MolSight-base checkpoint) and
**MolGlyph** (BioMiner's reader). BioMiner itself did not run (see "Why BioMiner did not run").

## 3. Reproducibility: MolScribe on the GPU vs the Mac CPU run

MolScribe was run on the same 237 MolDetV2 crops on the Mac CPU (2026-10-19) and on the AWS GPU.
The predictions are the same:

- **SMILES:** identical on all 237 crops, character for character. That includes the 16 crops whose
  output RDKit cannot read in either run, so 221 are valid in both.
- **Scores:** both give 51 of 219 molecules, recall 0.233. Every per-paper metric is identical
  except mean confidence.
- **The only difference is the confidence value.** It differs by at most 0.0000086 (median
  0.0000001). That is ordinary rounding: the CPU and the GPU add up floating-point numbers in a
  different order. The gaps are far too small to change which token MolScribe picks, so no
  prediction changed.
- Both runs used torch 2.14.1 (the arm64 CPU build on the Mac, the cu130 build on the instance).

Not related to accuracy: each crop took longer on the GPU (median 0.38 s) than on the Mac
(0.22 s). The cause was not looked into.

### The cuDNN mismatch and its fix

The first run (2026-11-03) gave MolScribe and MolSight 0.000 on every public set. Every image failed
with `cudnnFinalize failed ... CUDNN_STATUS_SUBLIBRARY_VERSION_MISMATCH`, so neither reader wrote a
SMILES.

- **Cause:** the AMI puts its own cuDNN 9.23.2 (`/usr/local/cuda-13.2/lib`) on `LD_LIBRARY_PATH`, from
  `/etc/profile.d/dlami.sh`. torch 2.14.1 loaded the core of cuDNN from its own package, then the
  engine libraries from the AMI's folder, and every convolution failed. `torch.cuda.is_available()`
  still returned True, so the old setup check passed.
- **MolGlyph was not affected:** it runs in BioMiner's conda environment, whose convolutions worked
  with the AMI's path set.
- **Fix (commit `b8a42f4`):** `run_all.sh` unsets `LD_LIBRARY_PATH` for every stage and gives it back
  only to the BioMiner servers. `setup.sh` now runs one real convolution on the GPU in each
  environment. A crop-reader stage now fails if a reader wrote no SMILES at all.
- **Proof on 200 USPTO images (198 scored):** MolScribe 0.929 [0.885, 0.957] against the published
  0.926, and MolSight 0.914 [0.867, 0.946] against the published 0.912.

### The MinerU OCR model

MinerU, inside BioMiner, still loads `models/OCR/paddleocr_torch/ch_PP-OCRv3_det_infer.pth`, which the
current `opendatalab/PDF-Extract-Kit-1.0` model pack no longer has. `setup.sh` downloads it from
commit `fe3643d1b873284fca2d90c3d731ffbc182b3566` (`fe3643d1b8`). On 2026-11-03 MinerU's `magic-pdf`
exited 0 after a crash, so the MinerU smoke test now passes only if it wrote a Markdown file.

### Why BioMiner did not run: the Gemini quota failure

Before the BioMiner stages, a smoke test runs BioMiner on its own example paper (`68_6r8r.pdf`) with
`gemini-3.5-flash` and the key set by `course_tier: paid`. It hit its 45-minute limit:

- 8 MLLM calls were answered.
- 21 attempts were refused with HTTP 429 `RESOURCE_EXHAUSTED` on Google's **free-tier** metric
  `generate_content_free_tier_requests`: 1 on the 5-requests-per-minute limit and 20 on the
  20-requests-per-day limit.
- 10 attempts got HTTP 503 ("high demand").
- 4 calls failed after all 6 tries.
- The errors name the model `gemini-3.6-flash`, although the config asks for `gemini-3.5-flash`.

So the "paid" key was held to free-tier limits, even though both keys passed a one-call test during
setup. Because the smoke test did not pass, `run_all.sh` skipped BioMiner on the course papers and
on the BioVista papers. MolRecBench-Wild was also skipped, because its data file was not on the
instance.

- **(a) All three agree:** the crops where all three readers give the same valid InChIKey, scored with that

- **(c) Top confidence:** MolScribe's highest-confidence crops, as many as in (a) or (b). There are no ties at either
  cutoff.
